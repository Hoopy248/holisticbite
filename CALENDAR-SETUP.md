# Календарь holisticbite

Кабинет: `/admin` или `/admin.html`. Готова интеграция с формой записи в `script.js`.

## Перед публикацией

В Vercel → Project → Settings → Environment Variables добавьте:

- `ADMIN_PASSWORD` — уникальный длинный пароль Даши (не демонстрационный).
- `ADMIN_SESSION_SECRET` — случайная строка минимум 32 байта. Например, сгенерировать локально: `node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"`.
- `UPSTASH_REDIS_REST_URL` и `UPSTASH_REDIS_REST_TOKEN` — адрес и полный токен постоянной базы Upstash Redis. Используйте отдельную базу для production и preview.
- Существующие `RESEND_API_KEY`, `RESEND_FROM_EMAIL`, `CONTACT_TO_EMAIL`, `SITE_URL` используются для писем.

Не добавляйте `CALENDAR_DEMO` на Vercel. Код дополнительно блокирует демонстрационный режим при наличии `VERCEL`.

REST-протокол проверен по документации: https://upstash.com/docs/redis/features/restapi . Изменения сохраняются атомарно через EVAL с проверкой предыдущей версии, поэтому две заявки на одно время не проходят одновременно.

После подключения базы: загрузите эти исходники в связанный с Vercel репозиторий и выполните deploy. Сборка `npm run build` обновляет `public/` из основных файлов проекта; API остаётся в `api/`, серверный модуль — в `lib/`. Корень проекта, рабочие файлы и инструкции не публикуются как статические файлы.

При первом входе расписание пустое: Даша задаёт настоящую неделю и часовой пояс, затем открывается запись. Ранее присланные по почте заявки не импортируются автоматически — перед открытием дней нужно закрыть уже занятые часы.

## Как пользоваться

1. Обычная неделя: выбрать часовой пояс, длительность (единая для всех форматов), ввести время начала консультаций через запятую.
2. Календарь: выбрать дату и сохранить отдельные часы, закрыть день либо вернуть обычное расписание.
3. Отпуск: указать первый и последний дни включительно. Новые записи закрываются, старые остаются.
4. Записи клиентов: посмотреть контакты и запрос. Перед отменой связаться с клиентом; автоматическое письмо об отмене не отправляется.

Все часы на сайте показаны в часовом поясе Даши. Новая запись доступна на 90 дней вперёд. Будущие встречи сохраняются при редактировании расписания. Изменить часовой пояс при активных будущих записях нельзя без согласования переноса.

## Локальная проверка

- `node --test work/calendar.test.cjs`
- `node work/calendar-preview.cjs`
- http://127.0.0.1:4188/admin.html ; пароль только для демо: `demo-holisticbite`.

Демонстрация хранит данные в памяти процесса, после перезапуска они исчезают. Реальные письма из демо не отправляются. Production при недоступном хранилище не показывает выдуманные свободные часы.

Проверены: вход и ограничение попыток, скрытие контактов от публичного API, проверка источника запроса, сохранение недели, исключения, конфликт версий, двойное бронирование, повтор заявки, пересечения длительности, сохранение встреч в отпуск, отмена, отсутствие базы. В браузере проверяются кабинет на телефоне и полный путь локальной записи.

## Ограничения

Письма отправляются после сохранения записи. Сбой почтового сервиса не отменяет бронь; заявка остаётся в кабинете. Автоматической повторной отправки писем нет. Авторитетный список записей — кабинет.
Календарь пока не синхронизируется с Google/Apple Calendar. Записи и расписание хранятся в одном документе Redis; этого достаточно для личной практики, но при большом объёме нужна отдельная таблица записей и политика архивирования.
